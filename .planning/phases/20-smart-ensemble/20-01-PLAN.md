# Plan: Smart Ensemble Weighting

## Objective
Implement dynamic weighting for the OCR ensemble consensus mechanism. Instead of "1 backend = 1 vote", weight backends based on their known strengths.

## Context
- **PaddleOCR** is generally better at digits and tables.
- **Claude** is better at Thai text and complex layouts.
- **Tesseract** is a solid baseline but often hallucinates on noise.

## Requirements
1. **Weight Configuration**: Define weights for each backend in `model_backends.py`.
   - e.g. `Paddle: 1.5`, `Claude: 1.2`, `Tesseract: 1.0`.
2. **Weighted Voting**: Update `_vote` function to calculate "weighted consensus".
3. **Form-Specific Weights**: Ideally, weights should vary by form type (Party-List forms might favor Paddle for the dense numeric table).

## Tasks

### 1. Update `model_backends.py`
- [ ] Add `weight` property to `ModelBackend` protocol.
- [ ] Set weights in concrete classes:
    - `PaddleBackend`: 1.5
    - `TrOCRBackend`: 1.2
    - `AnthropicBackend`: 1.2
    - `TesseractBackend`: 1.0
    - `OpenRouterBackend`: 1.0

### 2. Implement Weighted Voting
- [ ] Modify `_mode_with_fallback` or `_vote` to sum weights instead of counting occurrences.
- [ ] Example:
    - Paddle says "153" (weight 1.5)
    - Tesseract says "158" (weight 1.0)
    - TrOCR says "153" (weight 1.2)
    - "153" score = 2.7, "158" score = 1.0 -> Winner: "153".

## Technical Details

**Voting Logic:**
```python
scores = defaultdict(float)
for name, data in results:
    weight = BACKEND_WEIGHTS.get(name, 1.0)
    val = data.vote_counts.get(pos)
    scores[val] += weight
winner = max(scores, key=scores.get)
```

## Constraints
- Keep it simple. Hardcoded weights are fine for v2.0.
