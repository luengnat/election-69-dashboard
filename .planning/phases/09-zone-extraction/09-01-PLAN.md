# Plan: Zone-Based Extraction Implementation

## Objective
Implement precise, form-specific coordinate templates for all 6 Thai ballot form types to improve OCR accuracy and reduce token usage.

## Context
Currently, `crop_utils.py` uses a single generic `vote_numbers` crop region (right 34% of page) for all forms. While effective, it relies on a "one size fits all" assumption. v1.2 aims to define specific templates for each of the 6 form types (S.S. 5/16, 5/17, 5/18, plus their Party-List variants).

## Requirements
- **ZONE-01**: Define specific coordinate systems for each form type.
- **ZONE-02**: Update `crop_utils.py` to select the correct template based on detected form type.
- **ZONE-03**: Ensure fallback to full-page processing if cropping fails.

## Tasks

### 1. Analysis & Template Definition
- [ ] Analyze `FORM_CATEGORIZATION.md` and available test images to estimate coordinates.
- [ ] Define `FormTemplate` dataclass to hold regions for:
    - Header (for metadata verification)
    - Vote Column (main numeric region)
    - Summary Table (totals at bottom)

### 2. Refactor `crop_utils.py`
- [ ] Create `FormTemplates` registry dictionary mapping `FormType` to coordinate sets.
- [ ] Update `get_crops_for_ballot` to accept `FormType` and use the specific template.
- [ ] Maintain the generic fallback for unknown types.

### 3. Update `ballot_extraction.py` / `model_backends.py`
- [ ] Ensure `_extract_with_crops` passes the specific `FormType` correctly.
- [ ] Add logging to confirm which template is being used.

### 4. Verification
- [ ] Run `ballot_ocr.py` on test images.
- [ ] Verify that crops are generated correctly for identified forms.

## Technical Details

**Proposed Template Structure:**

```python
@dataclass
class FormCropTemplate:
    vote_column: tuple[float, float, float, float]  # (left, top, right, bottom)
    summary_section: tuple[float, float, float, float]
    # Optional: specific exclusion zones or secondary columns
```

**Estimated Coordinates (to be refined):**
- Constituency Forms (5/16, 5/17, 5/18): Candidates start lower on page 1 (~55% down).
- Party-List Forms (5/16 BCH, etc.): Header is smaller, table starts higher (~20-25% down).

## Constraints
- Must not break existing functionality.
- Must fall back gracefully if form type detection is wrong.
