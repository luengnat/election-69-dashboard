# Plan: PaddleOCR Backend Implementation

## Objective
Implement PaddleOCR as a high-performance local backend for OCR.

## Context
Tesseract is reliable but can be slow and less accurate on complex layouts compared to modern deep learning models like PaddleOCR. PaddleOCR offers excellent support for tables and digits, making it ideal for ballot forms.

## Requirements
1.  **Backend Class**: Create `PaddleBackend` in `model_backends.py`.
2.  **Configuration**: Add `PADDLEOCR` to `EXTRACTION_BACKENDS` env var handling.
3.  **Dependencies**: Check for `paddlepaddle` and `paddleocr` libraries.
4.  **Verification**: Verify it runs on the test images.

## Tasks

### 1. Check Dependencies
- [ ] Check if `paddleocr` is installed. If not, the backend should gracefully disable itself.

### 2. Implement `PaddleBackend` in `model_backends.py`
- [ ] Class `PaddleBackend` implementing `ModelBackend` protocol.
- [ ] `__init__`: Initialize `PaddleOCR(use_angle_cls=True, lang='en')` (or 'th').
- [ ] `extract`: Convert image to bytes/path -> `ocr.ocr(img_path, cls=True)`.
- [ ] Parse PaddleOCR output structure to `BallotData`.

### 3. Integration
- [ ] Update `build_backends_from_env` to support `paddle`.

## Technical Details

**PaddleOCR Output:**
```python
[
  [
    [[x1, y1], [x2, y2], [x3, y3], [x4, y4]], # bounding box
    ('text', confidence)
  ],
  ...
]
```
Need to parse this into lines/words and extract numbers similar to `TesseractOCR.extract_vote_counts`. Since PaddleOCR gives boxes, we can potentially sort by Y-coordinate to reconstruct rows more accurately.

## Constraints
- PaddleOCR installation can be heavy (requires `paddlepaddle`). We will treat it as an optional dependency.
